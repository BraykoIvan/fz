# Лендинг прототипа

Задача: MVP-001. Статус: визуальное направление получило положительную оценку; тексты перерабатываются на согласование. Дата: 15 октября 2026 года.

Заказчик отклонил подробные доски, затем минималистичный вариант из двух экранов и уточнил: «Выглядит ужасно. Сделай красисый лендинг». Текущий шаг — один выразительный лендинг с понятной формой проверки. Полные требования рабочего продукта остаются в [требованиях MVP](../site-audit/requirements.md).

## Один лендинг

- Сильный первый экран: выразительная типографика, композиция, иллюстрация продукта и заметная форма URL.
- Понятно, зачем проверять сайт: потенциальные проблемы, возможные санкции и план исправлений.
- Небольшие разделы о результате и четырёх согласованных проверках. Иллюстрация с подписью «Пример отчёта» — часть композиции лендинга, не отдельный экран.
- Бесплатность, отсутствие регистрации, PDF и объём проверки понятны посетителю. Нет вымышленных клиентов, отзывов, статистики или обещаний полного соответствия закону.
- По последнему поручению заказчика в текстах лендинга нет упоминаний MVP, первой версии и демо. Эти слова не нужны посетителю для понимания будущего сервиса; технический статус работы сохраняется в документации.
- Все тексты, включая пример задания, понятны владельцу сайта без технической подготовки: без названий компонентов, кода, «редиректов», «чекбоксов» и «таск-трекеров». Объясняем проблему, последствия и действия для исправления.
- Наполнение опирается на изучение конкурентов, но не расширяет согласованный состав проверок и не заимствует неподтверждённые гарантии, суммы или сроки.

## Ограничения этого шага

- Новый дизайн создаётся через Stitch MCP. Сейчас не создаются экран результатов, компонентная доска, отдельные мобильные артборды или макет PDF.
- Лендинг показывает предполагаемый продукт. Пример отчёта иллюстративный, сайт не сканируется; действующие правовые выводы не заявляются. Удаление служебных меток из макета не означает готовность аудита. Формы статического экспорта не должны сообщать о якобы выполненной проверке введённого сайта.
- Простота пользовательского пути сочетается с полноценным визуальным оформлением лендинга; прежний вариант пустой формы не используется.
- Остальные состояния приложения и shared-компоненты остаются задачами реализации прототипа. Сокращение текущего дизайн-шага не отменяет продуктовые требования и Storybook.
- Реализация приложения сейчас не начинается. Для следующего шага нужно согласовать новый лендинг из [design.md](design.md).
