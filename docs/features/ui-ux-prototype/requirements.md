# Первый вариант интерфейса

Задача: MVP-001. Статус: новый дизайн на согласование после отказа заказчика от прежнего варианта. Дата: 15 октября 2026 года.

Заказчик попросил начать заново: сделать 1–2 простых экрана, на которых пользователь быстро ориентируется. Предыдущие подробные доски и макеты отклонены. Полные требования рабочего продукта остаются в [требованиях MVP](../site-audit/requirements.md).

## Два экрана

1. **Ввод адреса.** Сразу понятны назначение, поле URL и действие «Проверить». Кратко указаны бесплатность, отсутствие регистрации и предел проверки. Без рекламных блоков и сложной навигации.
2. **Результат.** Сайт, выполненный объём, две демонстрационные находки, понятные исправления и скачивание PDF. Одна находка раскрыта: факт, действия, сведения владельца, критерии приёмки, правовое основание и санкции по категориям без общей суммы. Вторая показывает компактное состояние.

## Ограничения этого шага

- Новый дизайн создаётся через Stitch MCP. Визуальная система определяется этими двумя экранами; отдельная компонентная доска, мобильные артборды и макет PDF сейчас не нужны.
- Фейковый результат явно обозначен как демо. Числа иллюстративные, сайт не сканируется; действующие правовые выводы не заявляются.
- Простой текст, явные действия, минимум декоративных элементов. Дизайн должен помогать прочитать и исправить проблему.
- Остальные состояния приложения и shared-компоненты остаются задачами реализации прототипа. Сокращение текущего дизайн-шага не отменяет продуктовые требования и Storybook.
- Реализация приложения сейчас не начинается. Для следующего шага нужно согласовать конкретные два макета, приведённые в [design.md](design.md).
