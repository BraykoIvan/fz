# Документация проекта

- [Описание проекта](project.md): назначение, подтверждённые границы и вопросы для сбора требований.
- [Утверждённый стек и архитектура](tech-stack.md): backend, frontend, тестирование и эксплуатационные инструменты.
- [Требования к коду](code-standards.md): DRY, KISS, устойчивость backend, дизайн-система Stitch и shared UI.
- [Требования к документации](documentation.md): OpenAPI, описание всех API и фоновых процессов с Mermaid-диаграммами последовательностей.
- [Каталог потенциальных нарушений](violations.md): условия применимости, правовые основания, санкции, ограничения автоматизации и очередь реализации.
- [Требования бесплатного MVP](features/site-audit/requirements.md) и [согласованные решения](features/site-audit/decisions.md): первый набор проверок, PDF, общий результат на 24 часа, открытые вопросы.
- [План работ по MVP](mvp-plan.md): 22 задачи с зависимостями и критериями готовности — сначала 6 задач UI/UX-прототипа с фейковой проверкой, затем настоящий аудит.
- [UI/UX-прототип](features/ui-ux-prototype/requirements.md): сценарии MVP-001, [дизайн Stitch](features/ui-ux-prototype/design.md), экспорты и [согласования](features/ui-ux-prototype/decisions.md).
- [Процесс разработки](workflow.md): обязательные этапы, согласования, артефакты и критерии готовности.
- `features/<feature-id>/`: требования, дизайн, проверки и решения по каждой фиче.

Документацию API размещаем в `docs/api/`, фоновых процессов — в `docs/processes/` по мере появления реализации. Эти каталоги и продуктовые контракты пока не созданы.

Общие инструкции для ИИ-агента находятся в [AGENTS.md](../AGENTS.md).

Документация должна отражать фактическое состояние проекта. Для неподтверждённых решений указывай статус «предложение» или «открытый вопрос»; для согласованных — дату и ссылку либо точную ссылочную запись на сообщение заказчика. Не сохраняй секреты и персональные данные в примерах.
